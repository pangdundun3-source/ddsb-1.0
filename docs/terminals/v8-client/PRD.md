# 3 需求概述

## 3.1 需求背景

速豹系统（速报系统）是一套面向政府机构、企事业单位及大型组织的 AI 驱动事件速报与审核管理平台，由 V8 客户管理端、V8 审核上报 PC 端、V8 审核上报 H5 端和 MT 应用管理端四类终端组成，采用多机构 SaaS 架构。

V8 客户管理端面向机构侧管理员与审核员：承接 MT 下发的业务配置，维护本机构外部协作人员，并完成日常审核处置。本文档聚焦其中三个模块——**审核管理（不含审核统计）**、**外部联系人**、**系统管理**。

## 3.2 业务现状与建设必要性

**业务现状：**

**1、审核待办分散。** 同源重复报送、前置审核与终审评分交织，缺少统一待办工作台与批量处置能力。

**2、外部协作人员难管。** 网格员等外部人员通过服务号接入后，关注未激活、组织归属、角色权限、专班分组缺少一体化入口。

**3、机构配置边界不清。** 模板、审核流程、打分规则既要支持机构个性化，又要服从平台「系统默认」管控与客户端编辑开关。

**建设必要性：**

**1、审核闭环。** 在客户管理端提供「我的审核 → 详情裁决 → 审核记录」闭环，支撑同源合审、终审评分与入仓。

**2、外部人员体系。** 统一管理外部用户、组织、角色与分组，保障审核上报端登录与权限正确。

**3、机构业务配置。** 在系统管理中维护本机构配置，系统默认项只读启停，自定义项可增删改（受客户端编辑开关约束）。

## 3.3 业务需求

**1、审核管理（不含统计）**

审核员处理待办、同源批量匹配、单条/批量通过驳回、终审评分、审核流水查询与加入数据仓库。

**2、外部联系人**

管理服务号外部用户（邀请/启停/删除）、外部组织树、外部角色权限（上报员/审核员默认只读）、人员专班分组。

**3、系统管理**

维护模板配置、审核流程配置、审核打分规则、数据字典、邀请注册字段预览、增值业务申请（启停）。

## 3.4 业务目标

**1、审核效率：** 同源待办可批量处置；终审评分与首发/重复打标可落库。

**2、人员可控：** 机构用户名额默认上限 200；邀请受剩余名额约束。

**3、配置合规：** 系统默认项 100% 不可编辑删除；自定义项变更不影响平台母版。

# 4 功能概览与模块边界

## 4.1 端内定位

V8 客户管理端位于机构运营层：

* **← MT 应用管理端**：接收机构业务配置（模板、流程、打分、字典、增值业务）及客户端编辑权限。
* **→ 审核上报 PC / H5**：外部角色权限、邀请注册字段、报送模板与审核流程决定填报与审核表现。
* **↔ 数据仓库 / 公告等模块**：审核通过可加入仓库；本轮不展开仓库与公告详述。

# 5 用户角色与使用场景

## 5.1 用户角色

| 部门以及角色 | 描述 | 主要诉求 |
| ------ | --- | ---- |
| 机构审核员 | 处理本机构待审速报 | 快速通过/驳回、同源合审、终审评分 |
| 机构系统管理员 | 维护外部人员与业务配置 | 邀请用户、组织树、模板与流程配置 |
| 外部上报员（间接受益） | 在审核上报端填报 | 被邀请激活、按模板填报、被驳回后重提 |
| 外部审核员（间接受益） | 在审核上报端审核 | 角色权限正确、待办可见 |

## 5.2 使用场景

**场景一：审核员处理同源待办**

【角色】机构审核员

【页面】审核管理 - 我的审核

【操作】1. 进入「我的审核」；2. 打开「批量匹配」；3. 在同源簇点击「批量审核」选择驳回或通过；4. 终审件选择评分后确认。

【期望结果】1. 相同链接的多条待审合并处理；2. 非终审通过进入下一节点且不传分；3. 终审通过写入评分。

**场景二：管理员邀请外部用户**

【角色】机构系统管理员

【页面】外部联系人 - 外部用户数据 - 邀请用户

【操作】1. 确认剩余可用激活数 > 0；2. 选择激活码/二维码/链接邀请；3. 设置角色为上报员或审核员并生成。

【期望结果】1. 名额不足时禁止邀请；2. 激活后进入「已关注已激活」列表。

**场景三：管理员调整自定义打分规则**

【角色】机构系统管理员

【页面】系统管理 - 审核打分规则

【操作】1. 新增自定义打分规则并启用；2. 尝试编辑系统默认规则。

【期望结果】1. 启用一组后其他组自动停用；2. 系统默认仅可查看/启停，提示受平台管控。

# 8 非功能描述

## 8.1 性能需求

1、审核列表默认分页 10 条，筛选变更重置页码；

2、同源匹配仅对当前待审集合聚合，避免全量扫描阻塞交互。

## 8.2 安全需求

1、操作按角色权限点控制；无权限隐藏或禁用；

2、系统默认配置不可被机构端篡改删除；

3、邀请链接/二维码/激活码受名额与有效期约束。

## 8.3 兼容性需求

1、页面路由使用 hash 模式（`#/路径`）；

2、门户分栏联动依赖文档中的「对应页面」路由（含 `?module=`）。

# 3 需求概述

## 3.1 需求背景

速豹系统（速报系统）是一套面向政府机构、企事业单位及大型组织的 AI 驱动事件速报与审核管理平台，由 V8 客户管理端、V8 审核上报 PC 端、V8 审核上报 H5 端和 MT 应用管理端四类终端组成，采用多机构 SaaS 架构。

客户机构（租户）使用速报系统前，需要由平台运营方为其准备报送模板、审核流程、打分规则、增值业务等业务配置，并决定客户管理端能否自行修改这些配置。V1.0 版本需要一个面向平台运营方（MT 身份）的管理工具，统一维护全平台业务母版，并按机构单独调整业务配置，这就是 MT 应用管理端。

## 3.2 业务现状与建设必要性

**业务现状：**

\*\*1、业务配置无统一母版。\*\*报送模板、审核流程、打分规则等配置分散在各客户环境，字段口径、审核层级、评分标准不一，新机构无法快速复用成熟配置。

\*\*2、报送数据结构不统一。\*\*各机构自定义报送模板时，标题、内容描述等核心字段名称与必填规则各不相同，平台无法按统一口径汇总、检索与统计上报数据。

\*\*3、审核责任边界不清。\*\*审核流程中内部人员与外部机构人员的处理范围没有区分，跨机构指派缺少约束，容易出现越权审核或无人处理。

\*\*4、客户端改配置缺少管控。\*\*客户管理端能否增删改业务配置没有统一开关，平台无法按机构控制「允许客户自配」或「仅供客户查看」。

\*\*5、增值业务无法统一运营。\*\*批量审核、指令流转、系统公告、报送首发重复识别、外部审核等增值业务的名称、介绍与开通状态缺少平台级统一维护入口。

**建设必要性：**

\*\*1、统一业务母版的必然要求。\*\*通过全局业务配置维护模板、审核流程、打分规则与增值业务母版，新机构按母版初始化，保证全平台配置规范一致。

\*\*2、规范报送数据的必要举措。\*\*通过系统默认固定字段统一报送模板的前置字段，确保每条上报都具备标题与内容描述，为审核、检索、统计提供一致的数据结构。

\*\*3、厘清审核责任的关键支撑。\*\*通过「终审取内部、其余取外部、仅指定人员可跨机构」的处理人规则，明确各审核节点的责任主体，降低越权与漏审风险。

\*\*4、分级管控客户配置的现实路径。\*\*通过客户端编辑开关，平台可按机构、按模块决定客户管理端是否可以增删改，兼顾标准化管控与客户个性化需求。

## 3.3 业务需求

**1、首页统计**

展示平台机构总数、正式/试用机构数量、即将到期与已到期机构数量，各省份机构分布、正式/试用占比，以及近 1 个月到期机构清单，帮助运营人员及时跟进续费。

**2、全局业务配置**

维护全平台业务规则母版，包括模板配置（含系统默认固定字段）、审核流程配置、审核打分规则、增值业务；并设置各模块「客户端」编辑默认权限，新开通机构按母版与默认权限初始化。

**3、机构业务配置**

按机构单独维护模板、审核流程、审核打分规则、增值业务与数据字典，系统默认项受平台管控仅供查看，机构可新建自定义项；按模块控制该机构客户管理端「支持编辑」或「仅支持预览」。

## 3.4 业务目标

**1、配置标准化目标：全平台业务配置统一母版**

* 新开通机构 100% 按全局母版初始化模板、审核流程、打分规则与增值业务配置。
* 全平台新建报送模板 100% 带入固定字段，「上报标题」字段覆盖率 100%。

**2、管理效率目标：缩短机构配置上线周期**

* 新机构从开通到完成业务配置上线的周期缩短至 1\~3 天。
* 机构个性化配置在机构业务配置中一站式完成，无需研发介入。

**3、风险管控目标：审核责任清晰、客户配置可控**

* 审核流程终审节点 100% 由内部人员处理，非终审节点不跨机构匹配负责人与角色。
* 客户管理端的配置修改权限 100% 受客户端编辑开关控制。

**4、运营目标：增值业务统一运营**

* 增值业务名称与介绍由平台统一维护，修改后同步至全平台，口径一致率 100%。

# 4 功能概览、架构与配置映射

## 4.1 系统架构图

MT 应用管理端是速豹系统的平台运营中枢，位于四端的最上层：

* **MT 应用管理端 → V8 客户管理端**：MT 下发机构业务配置（模板、审核流程、打分规则、增值业务、数据字典）以及各模块的客户端编辑权限；客户管理端在「支持编辑」的模块中可增删改本机构配置，在「仅支持预览」的模块中只能查看。
* **MT 应用管理端 → V8 审核上报 PC / H5 端**：报送模板决定上报表单（含固定字段、链接截图）；审核流程决定审核节点与处理人；打分规则决定终审评分等级；增值业务决定可用的扩展功能。
* **MT 应用管理端 ↔ 第三方系统**：MT 系统（机构主数据、服务状态）；网页截图服务（链接字段原文截图）。

| 层级 | 模块 | 关系说明 |
| --- | --- | ---- |
| 运营层 | 首页统计 | 掌握平台机构规模与到期情况 |
| 配置层 | 全局业务配置、机构业务配置 | 全局母版 → 机构初始化 → 机构单独调整 → 下发客户端 |
| 外部系统 | MT 系统、网页截图服务 | 机构主数据、原文截图 |

## 4.2 配置下发流程

**1、全局母版 → 机构**

1. 平台在「全局业务配置」维护模板、审核流程、打分规则、增值业务母版，以及各模块客户端编辑默认权限；报送模板自带系统默认固定字段；
2. 新机构开通时复制一份全局母版作为该机构的初始化配置，母版内置项在机构端显示为「系统默认」；
3. 机构配置此后独立维护，全局母版后续修改不覆盖已开通机构的配置（增值业务名称与描述、明确选择「同时应用到已创建的机构」的客户端权限除外）。

**2、机构 → 客户端**

1. 平台在「机构业务配置」中为机构新建自定义项、启停配置项、开通增值业务；
2. 平台按模块设置该机构的客户端编辑开关；
3. 客户管理端读取机构配置与客户端编辑权限，决定是否展示新增、编辑、删除操作；审核上报端按机构配置渲染表单、流转审核与评分。

## 5.2 使用场景

**场景一：机构配置专员调整报送模板固定字段**

【角色】机构配置专员

【页面】全局业务配置 - 模板配置 - 模板设计器（机构侧同理）

【操作】1. 进入「全局业务配置」或「机构业务配置」，点击「模板配置」页签；2. 点击「新增」或「编辑」进入模板设计器；3. 将第 1 行「上报标题」改名为「舆情标题」，字数上限改为 30；4. 将第 2 行「上报内容描述」改为选填；5. 点击「保存模板配置」。

【期望结果】1. 第 1 行仍为锁定的单行文本且必填不可改，第 2 行仍为锁定的多行文本；2. 名称、填报提示、字数上限按修改后保存；3. 第 2 行必填可改回必填；4. 两行均不可删除、不可排序、不可切换字段类型；5. 全局与机构设计器规则一致。

**场景二：机构配置专员配置审核流程处理人**

【角色】机构配置专员

【页面】全局业务配置 - 审核流程配置 - 编辑审核流程层级设计

【操作】1. 进入「审核流程配置」页签，点击「逐级审核流程（组织树自适应）」的编辑按钮；2. 点击第 2 阶段「==机构逐级审核==」，处理人来源选择「归属外部机构角色」，外部处理角色选择「初审员」；3. 点击第 3 阶段「总机构终审并评分」，处理人来源选择「内部角色」，内部处理角色选择「总机构管理员」；4. 设置无处理人处理规则与审核超时提醒；5. 点击「保存模板配置」。

【期望结果】1. 流程保存成功，节点卡片副标题显示对应处理人来源；2. 初审节点只在上报人归属的外部机构内匹配初审员；终审节点由总机构内部的总机构管理员处理；3. 节点无可匹配处理人时按无处理人处理规则执行。

**场景三：超级管理员调整客户端编辑默认权限**

【角色】超级管理员

【页面】全局业务配置 - 审核打分规则

【操作】1. 进入「审核打分规则」页签；2. 点击标题行「客户端」开关，由「支持编辑」改为「仅支持预览」；3. 在「修改机构默认设置」弹窗中选择「仅对后续新增的机构生效」；4. 点击「确认修改」。

【期望结果】1. 提示「审核打分规则客户端默认已改为仅支持预览，仅对后续新增机构生效」；2. 之后新建的机构，客户管理端的审核打分规则只能查看；3. 已创建机构保持原有设置不变。

**场景四：机构配置专员为单个机构定制配置**

【角色】机构配置专员

【页面】机构业务配置

【操作】1. 进入「机构业务配置」，在左侧「已开通」页签搜索并选中目标机构；2. 在「审核打分规则」页签点击「新增」，创建该机构的自定义打分规则；3. 在「模板配置」页签将「客户端」开关切换为「仅支持预览」；4. 在「增值业务」页签将「指令流转」切换为「已开通」。

【期望结果】1. 自定义打分规则显示「自定义」标签，可编辑、删除；系统默认规则显示「系统默认」，仅可查看与启停；2. 提示「客户端模板配置仅支持预览」，该机构客户管理端的模板配置只能查看；3. 该机构开通指令流转，客户端可使用该业务。

**场景五：平台运维主管跟进到期机构**

【角色】平台运维主管

【页面】首页

【操作】1. 打开「首页」；2. 查看「30天内即将到期机构」数量与「近1个月到期机构」列表；3. 点击「导出数据」导出清单分派给商务；4. 点击机构名称进入机构详情跟进续期。

【期望结果】1. 统计卡片与列表按实时数据展示；2. 导出文件为「近1个月到期机构数据\_YYYYMMDD.csv」，包含完整 11 列；3. 点击机构名称进入对应机构的详情页。

**场景六：商务支持专家维护增值业务介绍**

【角色】商务支持专家

【页面】全局业务配置 - 增值业务

【操作】1. 进入「增值业务」页签，查看各业务的启用 / 禁用状态；2. 点击「批量审核」卡片右上角的编辑按钮；3. 修改描述后点击「保存并同步」。

【期望结果】1. 提示「「批量审核」已更新，并同步至全平台」；2. 全局与各机构的增值业务卡片均显示新的名称与描述；3. 启禁状态仍由平台后台控制，页面上不可切换。

## 7.1 与MT登录平台对接

1. 对接目的：应用管理端不单独提供登录页，平台运营人员在 MT 登录平台登录后，从 MT 工作台进入应用管理端，免二次登录；应用管理端据此识别当前账号并控制菜单与操作权限。
2. 对接方式：单点登录（SSO），HTTPS 加密传输；MT 登录平台签发登录凭证（Token），应用管理端校验凭证后建立会话。
3. 对接数据范围：

（1）登录凭证：Token 及有效期；

（2）账号信息：账号 ID、姓名、手机号（脱敏）、所属部门、角色；

（3）权限信息：可访问的菜单（首页、机构管理、全局业务配置、机构业务配置等）及操作权限。

4. 对接流程：

（1）用户在 MT 登录平台完成登录，进入 MT 工作台；

（2）在工作台点击「速豹系统 · MT应用管理端」，携带登录凭证跳转；

（3）应用管理端向 MT 登录平台校验凭证，获取账号与权限信息，按权限展示菜单；

（4）凭证临近过期时自动续期；用户在应用管理端点击「退出登录」时，同步注销 MT 登录平台会话并返回登录页。

5. 异常处理：

（1）未携带凭证或凭证无效、已过期：跳转 MT 登录页，登录成功后返回原访问页面；

（2）账号无应用管理端访问权限：提示「当前账号无权访问应用管理端，请联系管理员开通」；

（3）MT 登录平台不可用：页面提示「登录服务暂不可用，请稍后重试」，并记录异常日志。

## 7.2 与V8集成平台对接

### 7.2.1 页面嵌入（iframe）

1. 对接目的：机构管理及部分全局配置由 V8 集成平台统一维护，应用管理端直接嵌入其页面，避免重复建设、保持数据口径一致。
2. 对接方式：iframe 嵌入 V8 集成平台页面，登录态通过 MT 登录凭证传递，页面间通过跨窗口消息（postMessage）通信。
3. 嵌入范围：

| 应用管理端菜单 | 嵌入页面 | 说明 |
| --- | --- | ---- |
| 机构管理 | 机构列表、新增机构、机构详情、机构编辑 | 整个模块嵌入，含机构详情下的组织架构、用户、角色、业务配置等页签 |
| 全局业务配置 - 平台专属邀请配置 | 平台专属邀请配置界面 | 二级模块的配置区域嵌入，左侧模块菜单由应用管理端提供 |
| 全局业务配置 - 数据字典管理 | 数据字典管理界面 | 二级模块的配置区域嵌入，左侧模块菜单由应用管理端提供 |

4. 对接流程：

（1）用户点击对应菜单，应用管理端加载 V8 集成平台页面地址，并带上登录凭证、当前机构 ID（机构详情 / 编辑时）；

（2）V8 集成平台校验凭证与权限后渲染页面；

（3）嵌入页面内的保存、跳转等结果通过跨窗口消息通知应用管理端，应用管理端据此刷新相关数据（如首页机构统计、机构业务配置的机构列表）或给出提示；

（4）嵌入页面高度随内容自适应，不出现双层滚动条。

5. 异常处理：

（1）嵌入页面加载失败或超时（超过 15 秒）：显示「页面加载失败」占位及「重新加载」按钮；

（2）凭证失效：嵌入页面通知应用管理端，统一跳转 MT 登录页；

（3）无该页面权限：嵌入区域显示「暂无访问权限」。

### 7.2.2 机构数据

1. 对接目的：获取机构名称、所在地区、正式 / 试用状态、服务到期时间，支撑首页统计与机构业务配置的机构列表。
2. 对接方式：API 接口对接，HTTPS 加密传输；页面加载时实时查询，机构在 V8 集成平台新增、编辑后通过消息通知应用管理端刷新。
3. 对接数据范围：机构 ID、机构名称、所在地区、机构类别、行业、销售人员与电话、服务模式（正式 / 试用）、服务起止日期。
4. 对接流程：

（1）应用管理端携带登录凭证发起查询；

（2）V8 集成平台校验身份后返回机构数据；

（3）应用管理端按服务到期时间计算已开通 / 已到期、即将到期状态。

5. 异常处理：接口超时（超过 30 秒）自动重试 3 次，仍失败时页面显示错误占位并记录异常日志。

### 7.2.3 配置下发

1. 对接目的：下发机构业务配置与客户端编辑权限，保证 V8 客户管理端、审核上报端的表单、审核流转、评分与增值业务按 MT 配置执行。
2. 对接方式：共享配置服务，配置保存后实时生效。
3. 对接数据范围：

（1）报送模板：字段及控件类型、填报提示、必填、选项、字数上限、PC 端字段宽度、系统默认固定字段、链接截图能力；

（2）审核流程（节点、处理人来源、无处理人规则、超时提醒）、打分规则、增值业务开通状态、数据字典；

（3）各模块客户端编辑权限（支持编辑 / 仅支持预览）。

4. 对接流程：

（1）应用管理端保存全局或机构配置；

（2）配置服务更新机构配置版本；

（3）客户管理端、审核上报端读取最新配置，按客户端编辑权限控制新增、编辑、删除入口。

5. 异常处理：配置读取失败时客户端沿用上一版本配置并提示刷新；客户端提交被权限拦截时提示「当前模块仅支持预览」。

## 7.3 与网页截图服务对接

1. 对接目的：链接字段访问原文地址，可访问时返回原文截图，不可访问时返回网站的访问反馈，供填报人与审核人核对原文。
2. 对接方式：API 接口对接，HTTPS 加密传输，异步返回截图结果。
3. 对接数据范围：

（1）请求：原文网址；

（2）可访问时返回：截图图片地址、截图时间；

（3）不可访问时返回：失败标识「原文地址不可访问」及访问反馈（如页面不存在（404）、网站服务器错误（500）、无法连接到该网站 / 请求超时）。

4. 对接流程：

（1）前端校验网址：为空或格式错误时直接提示，不调用截图服务（规则见 6.2.1.7）；

（2）截图服务访问原文地址，判断是否可访问；

（3）可访问：生成截图，返回截图地址与时间；

（4）不可访问：返回「原文地址不可访问」及访问反馈，前端原样展示，用户可「重试」。

5. 异常处理：

（1）单次截图超过 15 秒视为不可访问，访问反馈为「无法连接到该网站，请求超时」；

（2）截图期间用户修改了网址，本次结果作废，不回填；

（3）截图服务本身不可用时，返回「原文地址不可访问」及访问反馈「截图服务暂不可用，请稍后重试」。

## 7.4 对接安全规范

1. 身份认证：用户相关接口与嵌入页面统一使用 MT 登录平台签发的登录凭证；服务间接口（如网页截图服务）携带 API 密钥，密钥定期更换（每 3 个月）；
2. 数据加密：采用 HTTPS 传输，敏感数据（手机号、登录凭证、API 密钥）加密存储与传输；
3. 权限控制：仅开放必要接口，客户端写操作需校验该机构该模块的客户端编辑权限；
4. 嵌入安全：V8 集成平台页面只允许被应用管理端域名嵌入（白名单）；跨窗口消息需校验来源域名，非白名单来源的消息一律忽略；登录凭证不在页面地址中明文长期保留；
5. 日志记录：接口调用（成功 / 失败）记录调用时间、调用方、接口地址、请求参数、响应结果与错误原因；
6. 异常监控：接口失败、超时、数据异常时及时通知系统管理员。

5、关键配置操作（全局母版修改、机构配置修改、客户端编辑权限修改、增值业务编辑）写入操作日志，记录变更前后内容。

## 9.2 原型与需求的差异（待确认）

以下为当前原型与本文档存在差异的地方，本文档按需求口径编写，需开发确认后修正：

1、**首页数据**：原型统计卡片、图表、到期列表为静态示例（如机构总数 31 与占比图总计 30 不一致、列表含剩余 45 天机构），统计卡片点击跳转未带入状态筛选；

2、**激活模板**：原型模板配置固定为报送模板，暂无报送 / 激活切换入口，激活模板的实名核验、适配角色配置不可达，需确认 V1.1 是否保留激活模板；

3、**最多 N 级审核**：原型保存后 N 值未正确保留（卡片固定显示「最多3级」），详情弹窗审批阶段与超时提醒为固定文案；

4、**无处理人策略显示**：原型详情弹窗将「阻断提报」显示为「跳过该节点」；

5、**指定人员必填**：原型未校验指定人员是否已选择；

6、**审核人员名单**：原型内部 / 外部角色与人员为示例数据，需对接内部角色权限、外部角色管理与人员数据；

7、**增值业务机构端过滤**：原型中全局禁用的增值业务在机构端仍显示且可开通，与管控说明不一致；

8、**机构端系统默认项**：原型中全局新增的模板 / 规则下发到机构后显示为「自定义」可被修改删除，模板「详情」仍可编辑保存，与「系统默认项仅可查看」不一致；

9、**提示显示**：原型中部分模块（增值业务编辑、模板保存）的操作提示未显示或重复显示；

10、**客户端编辑权限执行**：V8 客户管理端尚未按客户端编辑开关隐藏新增、编辑、删除操作；本地开发环境下 MT 与客户管理端配置不共享。

# 需求概述

## 需求背景

速豹系统（速报系统）是一套面向政府机构、企事业单位及大型组织的 AI 驱动事件速报与审核管理平台，由 V8 客户管理端、V8 审核上报 PC 端、V8 审核上报 H5 端和 MT 应用管理端四类终端组成，采用多机构 SaaS 架构。

客户机构（租户）要使用速报系统，必须先由平台运营方完成机构开通、服务期限授权，并为其初始化报送模板、审核流程、打分规则、激活码名额、数据字典等业务配置。V1.0 版本需要一个面向平台运营方（MT 身份）的管理工具，统一承担多机构开通运营与全局业务母版配置，这就是 MT 应用管理端。

## 业务现状与建设必要性

**业务现状：**

**1、机构开通依赖人工**：新客户上线需要研发或实施人员手工建库、改配置，开通周期长达数周，试用与正式服务期限无统一台账，到期续费容易遗漏。

**2、业务配置无统一母版**：报送模板、审核流程、打分规则、驳回理由等配置分散在各客户环境，标准不一，新机构无法快速复用成熟配置。

**3、商业化能力缺失**：增值业务（批量审核、截图取证、指令流转、系统公告、首发重复识别）无法按机构单独开通与管控，难以支撑套餐化售卖。

**4、运营过程无留痕**：平台管理员的开通、配置、启停等操作缺少统一日志，无法满足等保合规与责任追溯要求。

**建设必要性：**

建设 MT 应用管理端后，平台运营方可以在一个界面内完成机构开通、服务续期、业务配置下发与增值业务管控：新机构上线周期由数周缩短至 1~3 天配置完成；全平台业务母版统一维护，保障各机构配置规范一致；所有关键操作全程留痕，满足合规审计要求。

## 业务需求

**1、平台登录**

平台运营人员使用企业微信扫码登录，系统校验平台账号与权限后进入工作台。

**2、首页统计**

展示平台机构总数、正式/试用机构数量、即将到期与已到期机构数量，以及各省份机构分布、机构类型占比和近一个月到期机构清单，帮助运营人员及时跟进续费。

**3、机构管理**

实现机构的新增、查询、详情查看、基本信息修改、启用、删除，以及试用/正式服务的开通与续期；在机构详情中为单个机构维护专属业务配置（模板、审核流程、打分规则、激活码、增值业务、数据字典、公众号换绑）。

**4、全局配置**

维护全平台的业务规则母版（报送/激活模板、审核流程、审核打分规则、激活码默认额度、增值业务入口、数据字典、公众号接入与换绑规则）及系统运维策略（到期预警、试用默认天数、到期自动关停），新开通机构按母版初始化。

**5、系统管理**

维护平台运营账号与角色，查询系统登录日志与操作日志，满足安全审计要求。

## 业务目标

1、新机构从开通到完成配置上线的周期缩短至 1~3 天；

2、平台机构服务到期提醒覆盖率达到 100%，到期续费遗漏率降低 XX% 以上；

3、新开通机构 100% 按全局母版初始化业务配置，人工配置工作量降低 XX% 以上；

4、平台管理员关键操作日志留存率 100%，日志保存不少于 90 天。

# 功能概览与架构

## 系统架构图

MT 应用管理端是速豹系统的平台运营中枢，位于四端的最上层：

- **MT 应用管理端 → V8 客户管理端**：MT 开通机构并下发初始化业务配置（模板、审核流程、打分规则、激活码名额、数据字典、增值业务开关）；客户管理端在此基础上维护本机构配置，日常运营由客户管理端负责。
- **MT 应用管理端 → V8 审核上报 PC / H5 端**：激活模板、激活码名额决定一线人员能否激活绑定；报送模板、审核流程、打分规则决定上报与审核的表单和流转方式；公众号配置决定消息推送通道。
- **MT 应用管理端 ↔ 第三方系统**：企业微信（MT 平台账号扫码登录）；MT 系统（同步机构信息、销售对接人、人员）；微信公众号 / 开放平台（机构自有公众号接入与人员换绑）；短信平台（人员换绑提醒）。

| 层级 | 模块 | 关系说明 |
| --- | --- | --- |
| 接入层 | 企业微信扫码登录、工作台 | 平台运营人员统一身份入口 |
| 运营层 | 首页统计、机构管理（列表 / 开通 / 续期 / 详情） | 机构生命周期管理 |
| 配置层 | 全局配置（业务规则总库、系统运维策略）、机构专属业务配置 | 全局母版 → 机构初始化 → 机构可调整 |
| 支撑层 | 账号管理、系统日志 | 权限与审计 |
| 外部系统 | 企业微信、MT 系统、微信公众号 / 开放平台、短信平台 | 身份、机构主数据、消息通道 |

# 用户角色与使用场景

## 用户角色

| 部门以及角色 | 描述 | 主要诉求 |
| --- | --- | --- |
| 超级管理员 | 拥有系统所有功能模块与全部机构的最高管理配置与账号审计权限 | 管理平台账号与角色，兜底处理所有配置 |
| 平台运维主管 | 负责平台所有机构开通、服务运维、全局阈值配置与系统监控 | 快速开通机构、掌握到期情况、维护系统运维策略 |
| 机构配置专员 | 负责业务模板、审核打分模型、指标公式及数据字典的维护调优 | 维护全局业务母版，协助机构完成专属配置 |
| 系统审计管理员 | 独立负责安全合规审计、管理员行为轨迹追溯与日志导出 | 查询、导出登录日志与操作日志 |
| 商务支持专家 | 负责重点政企客户机构建档、合同生命周期跟进与配额追加 | 新增机构、续期、追加激活码名额、开通增值业务 |
| 商务代表 | 负责指定区域范围内的机构客户录入与日常沟通对接 | 查看负责机构的服务期限与到期提醒 |

## 使用场景

场景一：商务支持专家在「机构管理 - 新增机构」中检索 MT 系统机构并选择「试用」服务，期望一键完成机构建档并开通 30 天试用。

场景二：平台运维主管在首页查看「近 1 个月到期机构」，点击机构进入详情办理「开通服务」续期，期望机构服务不中断。

场景三：机构配置专员在「全局配置 - 业务规则总库」中设置标准报送模板和默认审核流程，期望后续新开通机构自动带上这套配置。

场景四：机构采编团队扩充时，商务支持专家在机构详情「激活码配置」中新增激活码名额，期望新人员可以立即扫码激活。

场景五：系统审计管理员在「系统日志」中按时间范围筛选操作日志并导出，期望追溯某次配置变更的操作人与变更前后内容。

## 登录（V1.0）

对应页面：`#/login`

对应代码：`速报系统-MT应用管理端/src/components/WechatQrLogin.tsx`

### 功能描述

平台运营人员使用企业微信扫码登录 MT 应用管理端；退出登录后返回登录页。

### 界面原型

见原型 `#/login`。左侧为「康奈网络MT管理系统」品牌区，右侧为「企业微信扫码登录」二维码卡片。

### 功能详述

| 功能点 | 操作 | 结果 | 异常描述 |
| --- | --- | --- | --- |
| 展示登录二维码 | 页面加载 | ① 展示企业微信登录二维码；② 底部提示「请使用企业微信扫描二维码登录」 | ① 二维码获取失败时显示错误占位并提供刷新 |
| 刷新二维码 | 点击二维码右上角刷新按钮 | 重新生成二维码，状态重置为「等待扫码」 |  |
| 扫码登录 | 用企业微信扫码并在手机端确认 | ① 扫码后二维码蒙层显示「已扫码，请在手机上确认」「等待移动端授权确认...」；② 授权成功显示「登录成功」「正在进入系统...」；③ 进入工作台 `#/portal` | ① 账号不是平台账号或已停用时，提示无权限并停留在登录页 |
| 退出登录 | 点击顶部栏「退出」 | 弹出确认框：标题「提示」，正文「确定是否退出当前账号？」，按钮「取消」「确定」；确定后清除登录态并返回登录页 |  |

### 业务规则

1、仅「系统管理 - 账号管理」中状态为启用的平台账号可以登录；

2、登录、登出、登录失败、异地登录等行为均写入「系统日志 - 登录日志」。

#### 业务规则

1、机构开通时按全局配置母版复制一份初始化配置；此后机构配置独立维护，全局母版修改不自动覆盖已开通机构（仅影响新开通机构）；

2、来自全局母版的内置项在机构端显示「系统默认」，机构端仅可查看与启停，不可编辑、删除；机构可新建「自定义」项，自定义项可编辑、删除；

3、编辑系统默认项时提示「系统默认配置受平台全局统一管控，机构端仅提供查看功能。如需个性化格式，请新建“自定义”规则。」；删除时提示「系统默认配置项受平台全局管控，机构端不可删除！」；删除自定义项需确认「确定要删除配置项“{名称}”吗？」；

4、激活码初始化名额取「全局配置 - 激活码配置」的默认额度；已绑定人数不得超过当前总名额；

5、增值业务仅在全局已启用时对机构可见，机构端开关即代表该机构是否开通；

6、自有公众号可录入多个，同时仅允许一个生效；人员换绑须在通道换绑完成后才能发起，且受「全局配置 - 公众号换绑」规则约束。

## 与MT系统集成

1、新增机构时，从 MT 系统按名称或简称检索机构，获取字段：机构全称、机构简称、机构类别、行业、所在地区、销售人员、销售电话；

2、机构详情「从MT同步人员」，获取机构绑定微信的人员：微信头像、微信昵称、关注时间；

3、机构开通状态、服务周期回传 MT 系统（待确认）。

## 与企业微信集成

1、登录页展示企业微信扫码二维码，扫码确认后获取企业微信用户身份，与「账号管理」中的平台账号匹配后登录。

## 与微信公众号 / 开放平台集成

1、机构录入自有服务号的原始 ID、AppID、AppSecret，系统校验接口连通性；

2、通道切换后，发稿推送与模板消息通过目标公众号发送；

3、人员换绑通过 UnionID 静默匹配、服务通知卡片、短信验证码、工作台扫码核身等方式完成。

# 补充说明

## 原型与需求的差异（待确认）

以下为当前原型与《需求功能确认单》《商业白皮书》存在差异或原型尚未体现的地方，需产品确认后更新：

1、**审核流程类型**：白皮书要求「常规 / 紧急（标黄）/ 重大（标红）」三类审核流程，原型实现的是「逐级审核 / 最多 N 级审核 / 直接总机构审核」三种流程模式，两者关系待确认；

2、**数据字典分类**：需求确认单要求「公告分类、公告紧急程度」，原型仅展示「审核驳回理由、人员标签」（另有「来源渠道」「紧急程度」数据未展示）；

3、**白皮书中的考核规则、统计指标、登录验证方式配置**：原型全局配置中暂无对应模块；

4、**套餐 / 版本**：白皮书提到机构详情包含套餐管理，原型仅有「试用 / 正式」服务模式，无套餐字段；

5、**机构手动停用**：原型不支持手动停用启用中的机构，仅依赖到期自动关停；

6、**机构端默认项管控**：原型中全局新增的模板 / 规则下发到机构后显示为「自定义」，可被机构修改删除，与「管控说明」不一致，本文档按「全局下发项机构端不可改删」编写；

7、**运营监控**：已从菜单移除，单机构运行数据是否需要在机构详情中补充展示待确认；

8、**首页统计**：原型数据为静态示例，本文档按实时统计口径编写，统计卡片点击跳转需带入对应状态筛选。

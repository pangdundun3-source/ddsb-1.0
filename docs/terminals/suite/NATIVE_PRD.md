# 3 需求概述

## 3.1 需求背景

速报系统（速豹系统）是一套面向政府机构、企事业单位及大型组织的 AI 驱动事件速报与审核管理平台，整合 Web 端、移动端 H5 与平台运营能力，覆盖事件上报、智能审核、流程协同、数据统计、权限管控等全流程，适配政企数字化办公需求。

系统以「快速上报、智能审核、全程留痕、数据驱动」为核心理念，通过 AI 多模态识别、智能文稿生成、同类型事件聚类、首发事件追溯、重复报送检测等能力，将传统「人工填报、经验审核」升级为「AI 辅助、标准管控」的数字化模式。

产品采用多机构 SaaS 架构，由四类终端协同：

| 终端 | 定位 | 典型用户 |
| --- | --- | --- |
| MT 应用管理端 | 平台运营与全局 / 机构业务配置 | 平台运营方（MT） |
| V8 客户管理端 | 租户级运营管理、审核归档、组织与业务配置 | 租户管理员（V8 客户） |
| V8 审核上报 PC 端 | 子机构范围内的报送、审核与本级组织管理 | 子机构管理员 / 网格员（PC） |
| V8 审核上报 H5 端 | 现场快速上报与移动审核 | 一线上报员 / 基层审核员 |

四端数据实时同步、业务联动；平台配置经机构下发后，决定填报表单、审核流程、打分规则与增值能力在客户端与审核上报端的表现。

## 3.2 业务现状与建设必要性

**业务现状：**

**1、上报效率低、信息质量参差。** 传统速报依赖人工填表，现场耗时长；上报人员能力差异导致关键信息缺失、描述不规范，加重后续审核负担。

**2、审核标准不统一、流程不透明。** 多级审核下判断标准因人而异；驳回与修改缺少全程留痕；流程僵化，难按事件紧急程度动态调整。

**3、重复报送严重、首发难追溯。** 同一事件多渠道重复上报浪费审核资源；「谁先发现、谁先上报」依赖人工排查，考核与响应成本高。

**4、组织与配置分散、规模化交付难。** 模板、审核流程、打分规则、字典与增值业务缺少平台母版与机构级管控；新机构上线周期长，客户能否自配缺少开关。

**5、数据统计滞后、决策支撑不足。** 统计多为事后汇总，维度单一；管理层缺少实时看板支撑精细化管理。

**建设必要性：**

**1、多端协同采集。** 以 H5 降低一线门槛，以 PC / 客户管理端承接管理与审核，实现「报得快、管得住」。

**2、AI 驱动审核管控。** 同源识别、首发追溯、重复检测与标准流程配置，统一审核口径并缩短处理时效。

**3、配置可下发、责任可厘清。** MT 维护全局母版并按机构调整；客户管理端在授权范围内自配；审核上报端按生效配置填报与流转。

**4、组织一体化与数据沉淀。** 统一机构树、人员、角色、群组与邀请激活；审核通过数据可入仓、可迁移，支撑统计考核与转办闭环。

## 3.3 业务需求

**1、MT 应用管理端（平台运营）**

* 企微扫码登录；首页掌握机构规模、占比与近月到期情况。
* 机构管理：机构增删改查、启停与服务开通；机构详情承接套餐 / 服务与机构级业务配置入口。
* 全局配置：维护全平台初始化默认的模板、审核流程、打分规则、激活码上限、数据字典与增值业务入口启禁。
* 系统管理：平台运营账号与角色；操作 / 登录日志。

**2、V8 客户管理端（租户运营）**

* 微信扫码登录（需客户管理端权限）；首页展示全域待审、驳回待处理、已采纳待转办、今日上报与子机构运行概况。
* 审核管理：待办统计与处置（采纳 / 驳回 / 打分）、同源批量、审核记录与入库；审核统计可导出。
* 数据仓库：仓库增删改启禁、库内筛选、批量迁移 / 移出、单条迁移与转办衔接。
* 统计 / 考核：全域机构与人员指标、榜单与导出。
* 公告管理：发布、草稿、接收人范围、撤回与删除。
* 用户与组织：系统账号、组织机构树、角色权限、人员分组与邀请。
* 其他业务配置：模板 / 审核流程 / 打分 / 字典 / 增值业务申请（承接 MT 下发，受客户端编辑开关约束）。
* 个人中心：资料、多机构切换、退出。

**3、V8 审核上报 PC 端（子机构枢纽）**

* 微信扫码登录（未激活引导至 H5 激活）。
* 首页：报送 / 审核待办、快速上报、消息通知。
* 报送管理：我的报送、报送记录、报送统计、新建报送。
* 审核管理：我的审核、审核记录、审核统计；详情支持同源选择性批量。
* 消息中心与个人中心；组织管理（本级用户 / 组织节点 / 角色 / 群组 / 激活码与邀请，受本级约束）。

**4、V8 审核上报 H5 端（一线移动）**

* 微信授权 / 激活绑定（扫码 → 身份校验 → 绑定机构与角色）；已激活免登。
* 首页：选模板新建报送、站内最新消息提示。
* 消息列表：已读未读、一键已读、公告详情与业务跳转。
* 我的报送 / 我的审核：统计、列表筛选、详情、驳回重提、删除、审核通过 / 驳回及同源批量。
* 我的：个人资料、报送 / 审核统计（时间范围筛选）。

## 3.4 业务目标

**1、效率目标**

* 一线单条上报时间由 5～10 分钟缩短至约 1 分钟内（AI 辅助 + 模板化）。
* 审核支持同源合审与标准流程，缩短单条审核时效，提升日均处理量。

**2、质量与合规目标**

* 模板化字段与固定核心字段保证报送结构统一；审核全程留痕，驳回必填原因。
* 首发 / 重复识别可支撑考核；重复报送率显著下降。

**3、配置与交付目标**

* 新机构按全局母版初始化，业务配置上线周期缩短至 1～3 天。
* 系统默认项受平台管控（机构端仅查看 / 启停）；自定义项与客户端编辑开关分级可控。

**4、运营与决策目标**

* 平台可监控机构规模与到期；租户 / 子机构可查看报送、审核、考核看板并导出。
* 已采纳数据可入仓沉淀，支撑转办与复盘。

| 层级 | 终端 | 关系说明 |
| --- | --- | --- |
| 运营层 | MT | 维护母版与机构服务；不直接做一线填报 |
| 租户层 | 客户管理端 | 承接配置，做全域审核、归档、组织与自配（受开关） |
| 执行层 | 审核上报 PC / H5 | 按生效模板填报、按流程审核；PC 侧重本级管理，H5 侧重现场 |

外部能力（概念）：企业微信 / 微信登录与公众号、网页截图、指令流转 / 舆情等增值对接由平台与租户配置决定是否启用。

## 4.2 配置下发流程

**1、全局母版 → 机构**

1. MT 在「全局配置」维护模板、审核流程、打分规则、激活码默认上限、数据字典、增值业务入口等母版；
2. 新机构开通时复制母版作为机构初始化配置，内置项在机构侧标记为「系统默认」；
3. 机构配置独立演进；全局后续修改默认不覆盖已开通机构（明确勾选「同步已有机构」或增值名称类例外除外）。

**2、机构 → 客户管理端 / 审核上报端**

1. MT「机构详情 / 机构业务配置」或客户管理端「其他业务配置」在授权范围内调整本机构模板、流程、打分、字典与增值申请；
2. 客户端编辑开关决定客户管理端对系统默认 / 自定义项是「可编辑」还是「仅预览」；
3. 审核上报 PC / H5 读取机构生效配置：动态渲染上报表单、匹配审核节点与处理人、应用打分等级与增值能力（如批量审核、首发 / 重复识别等）。

**3、组织与账号链路**

1. 客户管理端 / 审核上报 PC 维护组织树、角色、用户群组与邀请（激活码 / 二维码 / 链接）；
2. H5 完成激活绑定后，用户携带机构与角色进入报送 / 审核；
3. 名额与激活上限受 MT 授权与机构配额约束。

# 5 用户角色与使用场景

## 5.1 用户角色

| 部门以及角色 | 所属端 | 描述 | 主要诉求 |
| --- | --- | --- | --- |
| 平台运维 / 配置专员 | MT | 机构开通、母版与机构配置、到期与日志 | 标准交付、可控自配、掌握平台运行 |
| 超级管理员（平台） | MT | 最高权限兜底 | 策略与权限最终决策 |
| 租户管理员 | 客户管理端 | 全域审核、仓库、统计考核、组织与业务配置 | 管得住审核与人员，配得活规则 |
| 租户审核员 | 客户管理端 | 待办审核、入库、同源处置 | 审得准、处理快 |
| 子机构管理员 / 网格员（PC） | 审核上报 PC | 本级报送审核、本级组织与邀请 | 承上启下，本级闭环 |
| 上报员 | PC / H5 | 按模板上报、跟踪驳回重提 | 报得快、少返工 |
| 基层审核员 | PC / H5 | 移动或 PC 审核待办 | 随时审、同源一并处理 |
| 一线人员（微信） | H5 | 扫码激活、现场多素材上报 | 零安装、即开即用 |

## 5.2 使用场景

**场景一：平台开通新机构并下发默认配置**

【角色】平台配置专员（MT）

【路径】MT 登录 → 机构管理新增 / 开通服务 → 全局或机构详情确认模板、流程、打分、激活码上限与增值入口

【期望】新机构带入系统默认配置；客户管理端按客户端开关可见可配范围；审核上报端可按模板填报。

**场景二：一线扫码激活后现场上报**

【角色】上报员（H5）

【路径】扫机构码 / 激活码 → 校验姓名手机并绑定机构角色 → 首页选模板 → 填报（可含链接截图等）→ 提交审核

【期望】已激活再次打开免登；提交进入审核流程；弱网可先存草稿（能力以产品实现为准）。

**场景三：子机构审核员处理同源待办**

【角色】基层审核员（PC 或 H5）

【路径】我的审核 → 打开详情 → 查看流转 → 通过或驳回（必填原因）→ 对同源多条选择性批量

【期望】状态正确流转至下一节点或结束；列表与统计待办同步更新。

**场景四：租户终审并入库**

【角色】租户审核员（客户管理端）

【路径】我的审核 / 审核记录 → 采纳并打分 → 单条或批量加入数据仓库 → 必要时转办

【期望】已采纳数据进入指定仓库；支持后续迁移 / 移出与导出。

**场景五：租户邀请外部用户并限制群组**

【角色】租户管理员或子机构管理员

【路径】用户 / 组织管理 → 邀请用户（激活码 / 二维码 / 链接）→ 选择组织节点、用户群组、加入后角色与有效期 → 生成邀请

【期望】未选用户群组不可生成；受剩余名额与节点配额约束；受邀人激活后归属正确。

**场景六：运营查看到期机构**

【角色】平台运维主管（MT）

【路径】首页查看近一月到期机构 → 进入机构详情跟进续费 / 启停

【期望】到期清单可分页查看并进入详情，支撑续费运营。

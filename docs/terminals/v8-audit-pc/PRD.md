# 3 需求概述

## 3.1 需求背景

速豹系统（速报系统）是一套面向政府机构、企事业单位及大型组织的 AI 驱动事件速报与审核管理平台，由 V8 客户管理端、V8 审核上报 PC 端、V8 审核上报 H5 端和 MT 应用管理端四类终端组成。

V8 审核上报 PC 端面向机构内的**上报员**与**审核员**：上报员按模板填报、跟踪驳回与重提；审核员处理待办、同源合审与终审评分。本文档聚焦四个模块——**新建报送**、**报送管理（不含统计）**、**审核管理（不含统计）**、**个人中心**。

## 3.2 业务现状与建设必要性

**业务现状：**

**1、填报入口分散。** 首页快捷、侧栏新建、列表空状态多处触发，缺少统一的「新建报送」能力说明与模板套用规范。

**2、报送与审核割裂。** 待办、驳回重提、台账查询分散，缺少统一工作台与清晰状态流转。

**3、同源重复难处置。** 多网格员就同一链接/地址上报时，缺少批量匹配与联动审核能力。

**4、人员资料维护不便。** 实名信息、手机换绑、所属机构与角色查看缺少独立个人中心入口。

**建设必要性：**

**1、填报闭环。** 多入口汇入同一新建/编辑弹窗，模板套用后提交进入待审。

**2、报送闭环。** 「我的报送 → 详情 / 编辑重提 → 报送记录」形成完整闭环。

**3、审核闭环。** 「我的审核 → 详情裁决 → 审核记录」支撑单条与同源批量处置。

**4、账号自助。** 个人中心支持查看与维护基础资料、换绑手机。

## 3.3 业务需求

**1、新建报送**

多入口打开填报弹窗；首页「快速上报」模板快捷；选择报送模板套用样例；填写必填项并提交审核；驳回/草稿带入原文案后重新送审。

**2、报送管理（不含统计）**

我的报送待办、报送记录台账、详情查看、驳回后修改补充并重新提交、删除/撤回（按状态）。

**3、审核管理（不含统计）**

审核待办、同源批量匹配、单条/批量通过驳回、终审评分、审核流水查询与记录详情。

**4、个人中心**

微信号与实名信息展示、编辑资料、更换绑定手机、所属机构与角色展示（一人一机构）。

## 3.4 业务目标

**1、填报效率：** 模板/快捷一键套用；驳回可一键带入原文案重提。

**2、报送效率：** 待办与台账可追踪状态；支持删除/撤回（按规则）。

**3、审核效率：** 同源待办可批量处置；终审评分可落库。

**4、账号可信：** 手机换绑需验证码；敏感证件号支持脱敏与复制。

# 5 用户角色与使用场景

## 5.1 用户角色

| 部门以及角色 | 描述 | 主要诉求 |
| ------ | --- | ---- |
| 上报员 | 填报与跟踪本账号报送 | 新建、查看待办、驳回后重提 |
| 审核员 | 处理待审速报 | 通过/驳回、同源批量、终审评分 |
| 双角色用户 | 同时具备上报与审核权限 | 在顶栏切换模块完成两端工作 |

## 5.2 使用场景

**场景一：上报员新建并跟踪驳回**

【角色】上报员

【页面】新建报送 / 报送管理 - 我的报送

【操作】1. 首页「新建报送」或侧栏「新建速报」打开弹窗，选择模板填报提交；2. 被驳回后在我的报送打开详情；3.「修改补充并重新提交」。

【期望结果】1. 提交后进入待审核；2. 重提清空驳回信息并重新排队；3. 智能识别更新疑似首发/疑似重复。

**场景二：审核员同源批量驳回**

【角色】审核员

【页面】审核管理 - 我的审核

【操作】1. 打开「批量匹配」；2. 对同源簇点「批量审核」进入首条详情；3. 勾选伴报后确认驳回或通过。

【期望结果】簇内多条待审统一驳回，上报侧可见驳回原因。

**场景三：用户更换绑定手机**

【角色】上报员 / 审核员

【页面】个人中心

【操作】1.「更换」手机；2. 获取验证码并填写；3. 确认更换。

【期望结果】校验通过后手机更新成功；错误验证码提示不正确。

# 6 功能设计

*界面原型可在门户进入 V8 审核上报 PC 端后，点击本文模块标题在左侧原型中打开。功能详述表头为：**功能点 | 操作 | 结果 | 规则说明 | 异常描述**。*

## 6.1 新建报送

对应页面：弹窗（无独立 hash）；入口页 `#/home`、`#/report-summary`、`#/report-records` 等

对应代码：`速报系统-v8审核上报PC/src/components/NewReportModal.tsx`、`速报系统-v8审核上报PC/src/pages/Home.tsx`、`速报系统-v8审核上报PC/src/components/SideSubNav.tsx`

**功能描述**

上报员发起速报填报的统一能力：多入口打开同一弹窗；支持选择报送模板一键套用结构与样例；驳回件/草稿带入原文案后重新送审。

**界面原型**

居中弹窗。新建标题「新建速报」；驳回编辑「修改补充并重新提交」；草稿「编辑草稿速报」。首页右侧「快速上报」提供模板快捷入口。

**功能详述**

| 功能点 | 操作 | 结果 | 规则说明 | 异常描述 |
| --- | --- | --- | ---- | ---- |
| 打开新建 | 见 6.1.1 各入口 | 打开新建弹窗，默认套用「标准图文报送」等预设模板 | 上报员可见；纯审核员隐藏首页快速上报等入口 | — |
| 打开编辑 | 我的报送 / 详情「修改补充并重新提交」等 | 打开编辑弹窗并预填原文 | 驳回件展示驳回意见横幅 | — |
| 填报提交 | 见 6.1.2 | 进入待审核队列并智能识别 | — | 必填未填不可提交 |

**业务规则**

1、各入口共用 `NewReportModal`，不另开独立路由页；

2、模板数据来自 MT / 客户管理端下发的报送模板（原型为本地预设）；

3、提交后写入流转「提交上报」及待审节点。

### 6.1.1 入口与快速上报

对应页面：`#/home`（快速上报）；`#/report-summary` / `#/report-records`（侧栏与空状态）

对应代码：`速报系统-v8审核上报PC/src/pages/Home.tsx`、`速报系统-v8审核上报PC/src/components/SideSubNav.tsx`、`速报系统-v8审核上报PC/src/pages/ReportRecords.tsx`

#### 6.1.1.1 功能描述

汇聚打开新建报送弹窗的入口：首页「新建报送」与场景模板快捷、报送管理侧栏「新建速报」、报送记录空状态「立即新建上报」等。

#### 6.1.1.2 界面原型

见原型 `#/home` 右侧「快速上报」卡片；报送组侧栏底部「新建速报」按钮。

#### 6.1.1.3 功能详述

| 功能点 | 操作 | 结果 | 规则说明 | 异常描述 |
| --- | --- | --- | ---- | ---- |
| 首页新建 | 点击「新建报送」 | 打开空白新建弹窗（套用默认模板） | 上报员 / 双角色可见 | — |
| 首页快捷模板 | 点击「突发事件速报」「民生诉求核查」「网络谣言线索」等 | 打开弹窗并预填该场景标题、来源、区域、信息类型、摘要等 | 快捷项为首页场景入口，弹窗内仍可再换模板 | — |
| 侧栏新建 | 报送管理左侧「新建速报」 | 打开新建弹窗 | 在我的报送 / 报送记录等报送组页面可用 | — |
| 空状态新建 | 报送记录空态「立即新建上报」 | 打开新建弹窗 | — | — |
| 顶栏等其它入口 | 顶栏「新建」类入口（若有） | 同上打开弹窗 | 与侧栏共用同一 handler | — |

#### 6.1.1.4 业务规则

1、快捷模板仅预填，用户仍可在弹窗内修改全部字段；

2、纯审核员角色不展示首页「快速上报」区块。

#### 6.2.1.4 业务规则

1、列表排除「草稿」；

2、Tab「被驳回」匹配状态「被驳回」「已驳回」；

3、**状态打标前提**：所用报送模板的表单中**包含链接字段**才启用打标；无链接字段的模板整单不打标；链接为空或未填时不参与比对、不打标；

4、**比对数据范围（总平台）**：打标识别取**总平台**数据（跨机构、跨租户），不以本机构或本端可见范围为限；

5、**过程标识比对池**：`待审核 + 审核中 + 已采纳`（及同等「已通过」终态）；**被驳回 / 已驳回不计入**比对池（不占「最早提交」坑位）。详情若需提示「该链接历史上有过驳回」，仅作说明，不参与疑似首发 / 疑似重复判定；

6、**预判口径（过程标识）**：以**同一原文链接**为唯一比对键，在过程比对池内比较各上报事件的**提交时间**——池中该链接尚无人提过（或本条提交最早）→「疑似首发」；之后同链接再提交 →「疑似重复」；比对未完成时可为「识别中」。原疑似首发件若被驳回，即退出比对池，同链接其余在途件应重算过程标识；

7、**正式定标比对池与口径**：审核**通过 / 采纳**时，仅与总平台**已采纳库**比对同原文链接——库中尚无同链接已采纳件 → 定「首发报送」；已有 → 定「重复报送」（按**通过时间**先后）。过程中预判为「疑似首发」但未通过的件**不算**正式首发；驳回后重提按**新的提交时间**重新进入过程比对；

8、展示映射：待审核 / 审核中 / 被驳回阶段只展示过程态「疑似首发 / 疑似重复 / 识别中」；已采纳 / 已通过等终态才展示正式「首发 / 重复」（完整文案可为「首发报送 / 重复报送」）。

## 8.1 性能需求

1、列表默认分页（每页 10/20/50）；

1、按角色控制菜单与操作；

1、路由使用 hash 模式（`#/路径`）；

2、门户分栏联动依赖本文「对应页面」路由。

## 9.1 文档范围说明

# 速报系统门户界面优化设计方案

> 版本:v0.1
> 日期:2026-08-28
> 范围:统一入口门户(localhost:3003)首屏
> 原则:只出方案,不改代码

---

## 一、当前界面诊断

### 1.1 现有结构

当前门户共四段:

| 区域 | 内容 | 问题 |
| --- | --- | --- |
| 顶部栏 | Logo + "多端协同业务统一入口门户" + "四端系统在线"脉冲 | 状态表达弱,"四端在线"对用户没有决策价值 |
| 主标题区 | 徽标 + "点点速报系统" + "请选择对应的业务终端" | 纯静态欢迎语,没有告诉用户"接下来做什么" |
| 终端卡片 ×4 | 强调线 / 图标 / 分类徽标 / 中英文名 / 描述 / 端口地址 / 状态文字 / 箭头 | 信息过载,核心动作被淹没 |
| 底部栏 | 品牌名 + "TLS 1.3 / SSO" | 技术名词当产品文案,像文档不像产品 |

### 1.2 核心问题

1. **卡片是"信息表"不是"入口"**:每张卡片堆了 7~8 类信息,其中端口地址(3000~3004)对用户毫无价值,却占了一行主要位置;用户扫一眼不知道"该点哪张"。
2. **缺少角色代入**:文案都是功能名词(建档、配额池、OCR、GPS),不是"对你有用"的表达;没有待办、没有引导、没有最近使用。
3. **四端个性被压平**:四个终端各有业务语义(客户/现场/风控/运维),但简化版把所有视觉全部压成品牌蓝,用户无法靠颜色快速区分。
4. **状态不显性**:系统是否可用、终端是否在维护,只有一行小字和右上角脉冲,遇到"维护中"用户会误点。
5. **首屏没有"下一步"**:首次使用的人不知道从哪开始,门户也没有搜索或常用入口兜底。
6. **视觉细节粗糙**:卡片 hover 时图标块整块变蓝(过重)、数字无等宽处理、四张卡片同时动效缺乏层次、点击无按压缩放反馈。

---

## 二、设计目标

一句话:**把"选择终端"升级为"开始工作"**。

三个设计原则:

1. **一眼分清**(用户 3 秒内知道四个端分别是什么、哪个在维护);
2. **一步到位**(每张卡片只给一个主动作,入口即工作);
3. **克制的质感**(动效只服务引导,不喧宾夺主)。

---

## 三、推荐方案:门户 2.0(角色化导航)

### 3.2 各区域设计说明

#### A. 顶部栏

- 左:Logo + 产品名;
- 右:环境标识(测试/预发/生产,小圆点 + 文字)、系统健康度(如 99.9%),**替代**现在的"四端系统在线"脉冲;
- 未来登录后:右上角显示用户头像与角色,点击进入个人中心。

#### B. 角色问候区(Hero)

- 未登录:展示一句价值主张 + 三步骤引导(选择终端 → 进入工作台 → 完成速报);
- 已登录:问候 + 待办摘要(待办速报数、待审核数),右侧一个"查看工作台"主按钮;
- 作用:把首屏从"说明页"变成"开工页"。

#### C. 终端卡片(核心改造)

每张卡片只保留四类信息:

1. **图标 + 终端语义色**(客户=蓝、现场 H5=绿、风控 PC=紫、运维=琥珀),颜色差异帮助快速识别;
2. **名称 + 状态徽标**(在线/维护中/升级中,维护中卡片置灰并禁止点击);
3. **一句用户语言描述**:如"客户档案、配额与流水" → 改为"管理客户、划拨速报配额";
4. **一个主动作**:进入;H5 端额外提供"扫码进入"(二维码作为该端特色动作)。

移除项:英文名(降级为悬停提示)、端口地址(挪到卡片角标仅运维可见)、多余的"跳转链接"栏。

#### D. 辅助区

- 系统公告条:滚动/置顶展示维护通知,替代原来分散的状态文字;
- 最近使用:展示最近访问的 2~3 个终端,降低高频用户重复选择成本。

#### E. 底部栏

- 品牌 + 版本号 + 当前环境;
- "TLS 1.3 / SSO"等安全信息移到登录页或设置页,不再占用门户首屏。

## 四、视觉与交互细节(落地清单)

| 项 | 现状 | 优化 | 理由 |
| --- | --- | --- | --- |
| 卡片 hover | 图标块整块变蓝,背景变白 | 仅图标边框/阴影增强,图标颜色加深,保留语义色 | 整块填充过重,破坏终端个性 |
| 卡片进入动画 | 无 | 四张卡片依次入场,间隔约 100ms | 有层次的入场比同时出现更易读 |
| 按压缩放 | 无 | 卡片按下 scale 0.96 | 明确的触觉反馈 |
| 箭头位移 | 有(0.5px 平移) | 保留但统一为 2px | 动效克制且有方向感 |
| 数字排版 | 默认数字 | 待办数、健康度用等宽数字 | 数字变化时不抖动 |
| 标题换行 | 默认 | 标题用自动平衡换行 | 避免孤字断行 |
| 状态徽标 | 仅有文字 | 圆点 + 文字,维护中置灰禁点 | 状态一眼可见 |
| 命中区域 | 箭头框 32px | 提升到 40px+ | 点击更从容 |
| 焦点态 | 无 | 键盘导航时显示焦点环 | 可访问性 |
| 深色模式 | 无 | 预留明暗两套样式 | 兼容企业办公夜间场景 |

## 五、备选方案

### 方案 B:工作台模式(更激进)

登录后直接进入个人工作台(我的待办、快捷上报、审核队列、我的报表),四个终端收进左上角"应用"抽屉。门户从"导航页"变为"日常首页"。

- 优点:贴合高频用户,粘性最强;
- 成本:需要登录态与待办数据支撑,当前无后端时只能做模拟;
- 建议:作为门户 2.0 之后的演进方向,与后端能力同步落地。

### 方案 C:极简入口(最保守)

只保留四张卡片,删掉标题区装饰、footer 技术文案、卡片冗余信息,其余不动。

- 优点:改动最小、风险最低;
- 缺点:只解决视觉噪音,不解决"角色代入"与"下一步引导",提升有限。

---

## 六、实施建议

1. **本周(方案 A 视觉层)**:卡片信息重组 + 四色语义 + hover/入场/按压细节,纯前端即可完成;
2. **两周内(方案 A 信息层)**:环境标识、状态徽标、系统公告条接入真实状态(至少可配置);
3. **有后端后**:Hero 待办摘要、最近使用、登录态,进入工作台模式演进。

推荐先做方案 A,它是"投入产出比最高"的一步:不动架构、不改数据,只重构首屏信息与质感。

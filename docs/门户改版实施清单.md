## 一、数据结构调整

**位置**:`src/App.tsx:16-68`(`Terminal` 接口与 `TERMINALS` 数组)

### 1.1 `Terminal` 接口扩展

新增字段:

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `accent` | 颜色值 | 终端语义色(客户蓝 / H5 绿 / PC 紫 / 运维琥珀) |
| `status` | `'online' \| 'maintenance' \| 'updating'` | 终端状态,驱动徽标与是否可点 |
| `action` | `'enter' \| 'qr'` | 卡片主动作:H5 为扫码,其余为进入 |
| `primaryDesc` | string | 用户语言描述(替代原 `desc` 的功能名词) |

删除或降级字段:

| 字段 | 处理 |
| --- | --- |
| `enName` | 降级:不再渲染,改为悬停提示(title) |
| `statusText` | 由 `status` 派生,删除原文案 |
| `badge` | 保留但弱化(见 C 区) |

### 1.2 数据示例(以客户管理端为例)

```ts
{
  id: 'v8-client',
  name: '客户管理端',
  accent: '#1d61d6',
  status: 'online',
  action: 'enter',
  primaryDesc: '管理客户档案、划拨速报配额',
  url: TERMINAL_URLS.v8Client,
  icon: <Building2 />,
}
```

> 提示:`src/data/portalData.ts` 中已有更完整的 `TerminalItem` 模型(语义色、状态、指标、快捷入口),本清单先保持单文件改动;若后续要接增强版门户,可再整体迁移到该模型。

## 四、区域 C:终端卡片(核心重构)

**位置**:`src/App.tsx:114-186`

### 4.1 卡片结构(改后)

从上到下四层:

1. **顶部**:语义色强调线(沿用 134 行,颜色改为 `terminal.accent`);
2. **图标区**:语义色图标 + 状态徽标(在线绿点 / 维护灰点 / 升级琥珀点),弱化分类徽标;
3. **信息区**:端名称 + 一句用户语言描述(`primaryDesc`);
4. **动作区**:整卡可点 + 右下角主动作按钮(进入箭头 / 扫码图标)。

### 4.2 逐项改动

| # | 位置 | 操作 | 内容 |
| --- | --- | --- | --- |

### 4.3 语义色建议

| 终端 | 色值 | 含义 |
| --- | --- | --- |
| 客户管理端 | `#1d61d6`(品牌蓝) | 业务运营 |
| 审核上报 H5 | `#059669`(绿) | 现场/移动 |
| 审核上报 PC | `#7c3aed`(紫) | 风控/专职 |
| MT 应用管理端 | `#d97706`(琥珀) | 运维/系统 |

### 验收标准

- 3 秒内能区分四个端并说出各自用途;
- 维护中的端不可点击且有明确状态;
- 卡片上没有端口地址、"跳转链接"等噪音信息。

## 七、交互与细节清单(贯穿全页)

| # | 项 | 要求 |
| --- | --- | --- |
| F1 | 数字等宽 | 健康度、待办数使用 `tabular-nums`,避免数字变化抖动 |

| F8 | 深色预留 | 本轮不实现深色,但样式类避免写死纯白背景,保留扩展余地 |

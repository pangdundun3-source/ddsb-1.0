# 三端统计指标口径说明（开发交接）

> 口径原则：**以现有前端代码可推断的规则为准**；无法从业务上闭环的点标 **【待产品确认】**。  
> 覆盖端：V8 客户管理端、审核上报 PC、审核上报 H5。  
> 结构：**端 → 模块 → 页面 → 指标（含计算规则 / 数据来源）**。  
> 生成依据：仓库原型代码（2026-11-12）。

---

## 0. 阅读约定

### 0.1 数据来源类型

| 标记 | 含义 |
| --- | --- |
| **列表计算** | 对当前内存/mock 报送列表按状态过滤后实时算 |
| **近7日窗口** | 以列表中最新业务日期为锚点 `latest`，窗口 `[latest-6, latest]`（含首尾共 7 天） |
| **合成趋势** | `buildTrendSeries` / `seeded` 伪随机生成，**不是真实业务库** |
| **硬编码** | `metricsData` / 常量数字写死，仅演示 |
| **派生展示** | 由其他指标拆分展示（如采纳量拆首发/重复/其他） |

### 0.2 状态映射（客户管理端 / PC 中文态 ↔ H5 英文态）

| 业务语义 | 客户管理端 / PC `auditStatus` | H5 `status` |
| --- | --- | --- |
| 草稿 | `草稿` | `draft` |
| 待审核 | `待审核` | `pending_audit` |
| 审核中 | `审核中` | `auditing` |
| 已采纳（终审通过后数据态） | `已采纳` / `已通过` /（部分页含）`已转办` | `approved` |
| 已驳回 / 驳回待重报 | `被驳回` / `已驳回` | `rejected` |
| 待转办 | `待转办` | （H5 另有转办相关过滤，见各页） |

说明：节点操作叫「通过」，客户管理端终审通过后数据态视为「已采纳」。统计里常把 `已通过`/`已采纳`/`已转办` 一并算进采纳侧，**各页集合不完全一致，以该页公式为准**。

### 0.3 近7日锚点（多处共用）

```
latestDateKey = max(业务日期字段切片 YYYY-MM-DD)；无数据则取今天
recentStartKey = latestDateKey - 6 天
inRecentWindow(d) = recentStartKey ≤ d ≤ latestDateKey
```

业务日期字段因页面而异（`submitTime` / `createTime` / `auditTime` / `updateTime`），见各指标。

### 0.4 跨端「同名指标」口径差异（开发务必对齐）

| 指标名 | 客户管理端 `#/report-summary` | PC `#/report-summary` / H5 报送顶栏 | 说明 |
| --- | --- | --- | --- |
| 整体采纳率 | **全量列表** `采纳/总数` | **近7日** `采纳/近7日总数` | **不一致**【待产品确认】统一窗口 |
| 首审直通率 | 全量 `(总数-当前驳回存量)/总数` | 近7日 `(近7日总数-近7日驳回存量)/近7日总数` | 均为「用当前驳回状态近似」，非真实「从未驳回过」轨迹【待产品确认】 |
| 审核处理率 | 我的审核 / 审核统计各有定义 | PC/H5 我的审核与 Profile 定义略有差 | 见各节 |

- 路由：`#/audit-statistics`

- 趋势：`src/utils/statsTrend.ts` → `buildTrendSeries`

| 指标 / 区块 | 单位 | 计算规则（代码） | 数据来源 |
| --- | --- | --- | --- |
| 趋势·累计处理 | 次 | 序列字段 `audited`（合成） | 合成趋势 |
| 趋势·通过处理 | 次 | 序列 `passed` | 合成趋势 |
| 趋势·驳回处理 | 次 | 序列 `rejected` | 合成趋势 |
| 趋势·审核处理率 | % | 序列 `processRate` | 合成趋势 |
| 趋势·平均审核耗时 | 分 | 序列 `avgTime` | 合成趋势 |
| 环图中心·累计处理 | 次 | `metricsData.auditor` 周期切片硬编码；注释：**按审核动作计次，一件可多人处理重复计** | 硬编码 |
| 环图·通过处理 / 驳回处理 / 待办处理 | 次 | 同上硬编码分布 | 硬编码 |
| 平均审核耗时（卡片） | 分等 | `metricsData` 硬编码 + 展示格式化 | 硬编码 |
| 审核处理率（卡片） | % | 硬编码（如个人通过/总量文案） | 硬编码 |
| 全域对标表 | 多列 | 累计报送量、整体通过率、平均响应时效、综合总分等 | 硬编码表格 |

合成趋势单点公式（`buildTrendSeries`，客户/PC 共用思路）：

```
r = seeded(bucket.seed) ∈ (0,1)
dailyBase = 1380 + round(r*420) + (index%3)*40
total = max(20, round(dailyBase * spanDays * (0.92 + r*0.16)))
directRate = round1(74 + r*6 + (index%4)*0.4)
passRate = round1(min(99, directRate + 10 + r*3))
processRate = round1(95 + r*4)
closedRate = round1(91 + r*6)
rejected = max(1, round(total * (0.05 + r*0.04)))
passed = max(1, round(total * passRate / 100))
audited = max(passed, round(total * (0.9 + r*0.08)))
avgTime = round1(12.5 + r*3.5)
score = round1(86 + r*6)
```

**【待产品确认】** 大盘上线后是否全部改为真实聚合；「审核动作计次」与「按件计次」以哪套为准。

### 1.5 模块：考核管理

#### 页面：组织节点考核 / 人员考核

- 路由：`#/evaluation`
- 代码：`src/pages/EvaluationReference.tsx`

**考核周期常量**：`EVAL_PERIOD_DAYS = 30`（人员日均等用）。

#### 组织 / 群组榜字段（演示表 `orgRecords` / `groupRecords`）

| 指标 | 单位 | 规则 |
| --- | --- | --- |
| 人员参与 | 人 / % | 参与人数表 `orgParticipationCounts`；参与率=`参与/staff*100` |
| 累计报送量 | 件 | 表字段 `total`（硬编码行） |
| 累计采纳量 | 件 | `adopted`；再拆 **首发/重复/其他**：`other≈adopted*8%`，剩余按 hint 比例拆分 |
| 首审直通率 | % | 表字段 `directRate` |
| 整体采纳率 | % | 表字段 `passRate` |
| 平均审核耗时 | 分 | `avgTime` |
| 转办闭环率 | % | `closedRate`；导出时转办量≈`total*15%`，办结=`transferTotal*closedRate/100` |
| 审核处理率（派生） | % | `(adopted+rejected)/total*100` |
| 综合得分 | 分 | 表字段 `score`（组织行为硬编码） |
| 等级 | — | `≥95 卓越；≥92 优秀；≥88 良好；否则 合格`（按 `avgScore`/`score` 场景） |

#### 人员·网格员行（算法生成）

```
total、directRate、passRate ← seeded 伪随机
directCount = total * directRate / 100
adoptedCount = total * passRate / 100
综合得分 score = round1(adoptedCount * avgScore)   // 采纳件数 × 均分
```

#### 人员·审核员行（算法生成）

含：审核处理量、通过/驳回、`auditProcessRate`、`avgResponseMin`、`avgScore` 等（同文件 `auditorRecords` seeded）。

**【待产品确认】** 综合得分权重模型（雷达「采纳质量/时效/闭环」仅为展示加分文案，非正式权重公式）；组织 `score` 与人员 `adopted*avgScore` 两套是否统一。

#### 报送统计块

| 指标 | 规则 |
| --- | --- |
| 累计上报 | 周期内非草稿件数 |
| 累计采纳量 | `approved` |
| 审核中 / 待审核 / 被驳回 | 对应 status |
| 整体采纳率 | `approved / 累计上报 * 100` |

#### 审核统计块（按审核动作计次，注释对齐 PC/客户）

| 指标 | 规则 |
| --- | --- |
| 累计处理 | `通过处理 + 驳回处理`（`approved + rejected`） |
| 通过处理 / 驳回处理 / 待办处理 | 待办=`pending_audit\|auditing` |

## 4. 指标词典（建议后端统一实现）

下列为开发落地时建议的**目标口径**草稿；与原型不一致处已标差异。标 【待产品确认】 的需产品拍板后再写死接口。

| 指标 ID | 名称 | 建议公式 | 原型差异 |
| --- | --- | --- | --- |
| `todo_report` | 报送待办 | 待审核+审核中+驳回待重报（非草稿） | 客户 `#/report-summary` 卡片主数仅用驳回 |
| `todo_audit` | 审核待办 | 当前待我审（通常=待审核） | 一致居多 |
| `adopted_cnt` | 累计采纳量 | 终态∈{已采纳,已通过,已转办?} 且时间落在统计周期 | 是否含已转办【待产品确认】 |
| `adopt_rate` | 整体采纳率 | `adopted_cnt / submitted_cnt` | 窗口：工作台近7日 vs 大盘可选周期 |
| `first_pass_rate` | 首审直通率 | **建议**：周期内「首次审核结论为通过且历史无驳回」的件数 / 周期上报数 | 原型用「总数−当前驳回存量」近似 |
| `audit_process_rate` | 审核处理率 | **建议 A** 周期已处理/周期到达；**建议 B** 已处理/(已处理+待办) | Profile 用 B，AuditView/我的审核用 A |
| `avg_audit_response` | 平均审核响应/耗时 | mean(本环节完成时间 − 到达本环节时间) | H5 用 create→update；客户用 arrivedAt→auditTime |
| `transfer_closed_rate` | 转办闭环率 | 办结转办数 / 转办发起数 | 考核里用 `total*15%` 反推，非正式 |
| `audit_action_cnt` | 累计处理（动作） | 审核动作流水条数（通过+驳回，可多人） | 大盘注释采用；件维度需另指标 |

## 6. 交给开发前建议优先确认的产品点

1. **整体采纳率 / 首审直通率**：工作台是否统一「近7日」；客户 `#/report-summary` 是否改正。  
2. **首审直通**：是否改为真实「无驳回历史」事件口径。  
3. **审核处理率**：统一用「到达/已处理」还是「已处理/(已处理+待办)」。  
4. **采纳集合**：是否包含 `已转办`；与「已采纳」终态命名如何入库。  
5. **统计管理 / 考核大盘**：上线是否废弃合成趋势与硬编码，全面接数仓/明细聚合。  
6. **转办闭环率、综合得分权重**：补正式公式后再开考核接口。

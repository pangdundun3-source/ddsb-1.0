速报系统 · 流转状态设计说明

适用端：审核上报 H5 / 审核上报 PC / 客户管理端详情页 · 模块名称：流转状态

一、通用规则

  1. 模块标题：流转状态
  2. 展示顺序：时间倒序——最新节点在上，最早节点在下
  3. 原则：未发生的后续环节不预展示（例如「审核中」不出现终审、结束等待节点）
  4. 节点结构：左侧时间轴圆点 + 节点标题 + 内容卡片

1. 节点态视觉

节点态含义建议视觉
已完成已办结环节绿色勾
进行中 / 待处理当前待办橙色时钟
已驳回驳回环节红色感叹号

2. 卡片字段

字段说明
处理人姓名；已办结可带头像；多人时并排/多行展示
组织部门路径，如「市委宣传部舆情科」
时间已办结显示；待办可不显示时间
状态文案右上角：已提交 / 已通过 / 待审核 / 被驳回(或已驳回) / 已采纳 等
驳回原因仅驳回节点，红底说明块
评分仅终审通过节点，绿底「评分：xx分」

二、各业务状态下的节点清单

1）待审核

正序节点标题状态文案展示信息
1提交上报已提交报送人 · 组织 · 提交时间
2审核处理待审核多人待办（示例：王主任、李审核 · 市委宣传部舆情科）；可不显示时间
页面倒序展示：先「待审核」，下为「已提交」。

2）审核中

正序节点标题状态文案展示信息
1提交上报已提交报送人 · 组织 · 时间
2审核处理已通过王主任 · 市委宣传部舆情科 · 时间
3审核处理待审核多人待办（示例：李明、周复核 · 市网信办复核组）
不展示终审、结束等后续未发生节点。

3）已驳回 / 被驳回

正序节点标题状态文案展示信息
1提交上报已提交报送人 · 组织 · 时间
2审核处理被驳回 / 已驳回审核人 · 组织 · 时间 + 驳回原因（红底说明）
报送侧常用「被驳回」，审核侧常用「已驳回」。

4）已采纳（及已通过 / 待转办 / 已转办）——完整链路

上报 → 驳回 → 上报 → 通过 → 驳回 → 上报 → 通过 → 通过 → 通过 → 结束

结束节点状态文案

速报整体状态结束节点文案补充说明
已采纳已采纳—

页面倒序展示：最上为「结束 / 已采纳」，最下为最早一次「提交上报」。

三、建议设计稿覆盖场景（4 张）

  1. 待审核（2 节点，含多人待办）
  2. 审核中（3 节点，含已通过 + 多人待办）
  3. 已驳回（含驳回原因块）
  4. 已采纳完整链路（10 节点倒序，含两次驳回、三次上报、终审评分）

四、设计提示

  • 同一标题「审核处理」「提交上报」会多次出现，不要做成固定 5 步模板，应按真实发生节点纵向堆叠。
  • 待办多人：头像 + 姓名并排，状态「待审核」。
  • 已办结单人：头像 + 姓名 · 组织 · 时间，状态「已通过 / 已提交」。
  • 驳回必须露出原因文案区；终审通过额外露出评分区。
  • H5 与 PC / 客户管理端信息结构一致，可一套组件两端适配。

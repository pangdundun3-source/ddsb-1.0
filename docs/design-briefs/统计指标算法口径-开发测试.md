## 1. 通用约定

### 1.1 时间字段（禁止混用）

| 字段名（产品） | 字段名（建议代码） | 定义 | 典型用途 |
| --- | --- | --- | --- |
| 报送时间 | `submitTime` | 报送人**首次提交**该条速报的时间 | 累计报送、今日上报、采纳率分母时间窗 |
| 到达时间 | `arrivedAt` | **上一环节提交到本环节**的时间：首环节 = 报送时间；后续 = 上一审核人处理完成并流转到本环节的时间 | 待审核列表展示、审核处理率分母、平均审核耗时起点 |
| 办结时间 | `auditTime` / 本环节处理完成时间 | 本环节审核动作完成时间（通过 / 驳回 / 转办等） | 累计处理分子时间窗、平均审核耗时终点 |
| 采纳时间 | 终审采纳落库时间 | 终审通过并进入「已采纳」的时间 | 报送记录「采纳时间」、按采纳日筛选 |

**列表文案**：我的审核待办上的时间展示为「到达时间」，不得写成「上报时间 / 报送时间」。

### 1.2 状态集合

| 集合名 | 包含状态 | 说明 |
| --- | --- | --- |
| 采纳 | `已采纳` ∪ `已通过` | 终审通过后的采纳态；统计「采纳量」用此集合 |
| 驳回 | `被驳回` ∪ `已驳回` | 驳回待重报 / 驳回整改 |
| 在审 | `待审核` ∪ `审核中` | 尚未办结 |
| 通过类（本环节） | 本环节动作为通过 / 转办通过等 | 用于「通过处理」 |
| 驳回类（本环节） | 本环节动作为驳回 | 用于「驳回处理」 |
| 已办（本环节） | 通过类 ∪ 驳回类 ∪ 已转办（若本环节有转办办结） | 用于「累计处理」「审核处理率」分子 |
| 首发 | 正式标签：`首发` / `首发报送`（过程态「疑似首发」**不计入**采纳结构正式分桶，除非产品另行规定） | |
| 重复 | 正式标签：`重复` / `重复报送` | |
| 其他 | 已采纳但非首发、非重复（无标签或「其他」） | |

### 1.3 统计窗

| 窗类型 | 规则 | 默认用于 |
| --- | --- | --- |
| 存量 | 不过滤日期 | 首页待办类卡片 |
| 今日 | 自然日（系统时区），按**报送时间** | 今日上报 |
| 近 7 日 | 以「数据最新日」或「今天」为锚的滚动 7 天（两端实现须一致，见 §7） | 我的审核 / 我的报送工作台 KPI |
| 用户周期 | 页面日期控件起止 + 粒度（日/周/月…） | 统计页趋势 / 环状 / 考核 |

**率指标时间对齐**：

- **审核处理率**：分子按**办结时间**入窗；分母按**到达时间**入窗。
- **采纳率 / 直通率 / 报送量**：默认按**报送时间**入窗（采纳量若产品要求按采纳日，须在页面注明）。

### 1.4 空值与除零

| 场景 | 处理 |
| --- | --- |
| 分母 = 0 | 率显示 `--` 或 `0%`（两端统一为 `--`，测试按 `--` 验收） |
| 无可算耗时样本 | 平均审核耗时显示 `--` |
| 到达时间缺失 | 回退为报送时间，并打日志 / 埋点（便于排障） |
| 办结时间 < 到达时间 | 该条不参与平均耗时；不计入异常拉高 |

### 1.5 权限与范围

| 端 / 模块 | 数据范围 |
| --- | --- |
| 客户管理端 · 首页 / 统计 / 考核 | 当前登录客户可见组织树范围内 |
| 客户 · 我的审核 | **当前审核人**待办 / 已办 |
| PC · 首页 / 我的审核 | **当前用户**待办 |
| PC · 我的报送 / 报送统计 | **当前用户**作为报送人的数据（机构管理员若可看全机构，以实现权限为准，须在用例标明角色） |

## 2. 核心公式（全站复用）

### 2.1 审核处理率（%）

```
审核处理率 = round( 已办数 / 到达数 × 100 , 1 )
```

- **已办数**：统计窗内，`办结时间` 落窗，且状态 ∈ 已办  
- **到达数**：统计窗内，`到达时间` 落窗的件数（含仍在审、已办、已驳回等「曾到达本视角」的件）  
- **不是** `通过数 / 总数`。考核表若展示「通过数/总数」，那是**附带拆分展示**，处理率本身仍用本公式。

### 2.2 平均审核耗时

```
单条耗时 = 办结时间 − 到达时间
平均审核耗时 = avg(各已办条的单条耗时)
```

- 仅统计已办且耗时合法的样本。  
- 展示：&lt; 60 分用「X 分」；≥ 60 分可用「X.X 时」；≥ 24 时可用「X.X 天」（与现网格式化函数对齐即可）。

### 2.3 整体采纳率（%）

```
整体采纳率 = round( 整体采纳数 / 报送数 × 100 , 1 )
```

- **报送数**：窗内按报送时间计数  
- **整体采纳数**：上述报送中，最终状态 ∈ 采纳  

### 2.4 本地采纳率（%） / 本地采纳量

```
本地采纳量 = count( 在本组织节点审核链路内被采纳的件 )
本地采纳率 = round( 本地采纳数 / 本范围报送数 × 100 , 1 )
```

- **本地**：统计对象所属组织节点（或考核行对应节点）视角下的采纳。  
- **整体**：总平台终审采纳（可跨节点）。  
- 同一条可同时计入本地与整体；两者分母通常同为该范围报送数。

### 2.5 直通率（%）（首审直通率）

```
直通件 = 报送后从未被驳回，且最终 ∈ 采纳
直通率 = round( 直通件数 / 报送数 × 100 , 1 )
```

- **禁止**用「当前状态 ≠ 驳回」代替（会把待审/审核中算进直通）。  
- 驳回后重报再通过 → **不算**直通。  
- 仍在审、未采纳 → **不算**直通（分子不含）。

### 2.6 转办闭环率（%）

```
转办闭环率 = round( 转办已办结数 / 转办发起数 × 100 , 1 )
```

- **转办发起数**：窗内发起过转办的件数（按发起时间）  
- **转办已办结数**：其中转办目标侧已处理完成（通过/驳回/再流转结束等，按转办工单终态）

### 2.7 综合得分 / 平均得分

```
平均得分 = Σ(已计分采纳件的得分) / 已计分采纳件数
综合得分 = Σ(已计分采纳件的得分)
         或 = 采纳件数 × 平均得分   // 二者等价于「每件都有分」时
```

- 仅**已采纳且已打分**的件计入。  
- 首发 / 重复 / 其他：按正式标签对得分或件数分桶后求和。

### 2.8 人均类

```
人均报送 = 累计报送量 / 报送人员数
人均负荷 = 累计处理量 / 考核天数
```

- **报送人员数 / 审核人员数**：在册人数（页面若写「报送人员」「审核人员」即此）。  
- **人均负荷**单位：次/人·日（日均处理量）；考核天数取页面所选周期天数（如 30）。  
- 人数 = 0 时显示 `--`。

### 2.9 人员参与

```
人员参与 = 活跃人数 / 在册人数
展示：活跃/在册（可同时给百分比）
```

- 活跃：周期内有过报送或审核动作的人（报送人员活跃 + 审核人员活跃，按矩阵行定义汇总）。

## 4. 测试验收要点（抽检用例逻辑）

### 4.1 到达时间 vs 报送时间

| 步骤 | 期望 |
| --- | --- |
| 报送人 10:00 上报 → 一审待办 | 一审看到到达时间 = 10:00（= 报送时间） |
| 一审 11:00 通过并流转二审 | 二审看到到达时间 = 11:00；报送时间仍为 10:00 |
| 计算二审耗时 | 用二审办结时间 − 11:00，不得用 10:00 |

### 4.2 审核处理率

| 数据 | 期望 |
| --- | --- |
| 窗内到达 10 件，办结 7 件 | 处理率 = 70.0% |
| 窗内到达 0 | 显示 `--` |
| 办结日在窗内、到达日在窗外 | 计入分子、**不**计入分母 |

### 4.3 直通率

| 数据 | 期望 |
| --- | --- |
| 报送 5；其中 3 从未驳回且已采纳；1 驳回后重报采纳；1 待审 | 直通率 = 3/5 = 60.0%（待审、驳回重报均不计直通） |

### 4.4 采纳率

| 数据 | 期望 |
| --- | --- |
| 报送 10，采纳 8 | 整体采纳率 = 80.0% |

### 4.5 人均负荷

| 数据 | 期望 |
| --- | --- |
| 周期 30 天，累计处理 60 | 人均负荷 = 2.0（次/日） |

### 4.6 首发 / 重复 / 其他

| 数据 | 期望 |
| --- | --- |
| 采纳结构副文案 | 首发 + 重复 + 其他 = 累计采纳量 |
| 仅有「疑似首发」未终审 | 不计入正式首发桶 |

## 7. 待产品拍板（实现前确认）

1. **近 7 日锚点**：以「今天」还是「环境数据最大日期」？两端必须相同。  
2. **本地采纳**边界：是否 =「本节点终审通过」？上级节点看下级时，本地是否含下级？  
3. **综合得分**是否另有权重表（质量分、时效分），还是仅 Σ 采纳得分？  
4. **人均负荷**分母固定「考核天数」还是「审核人数」？（本文件按**考核天数**；若改人数，测试用例同步改。）  
5. **环状扇区**是否要求与中心数字加总相等（互斥拆分），允许「采纳」与「状态扇区」两套口径并存时须在 UI 区分。

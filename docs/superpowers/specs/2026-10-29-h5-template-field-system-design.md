# H5 上报模板字段体系设计

## 目标

让 H5 上报首页的四个模板具备真实模板差异，同时保持现有上报、审核人阻断和审核流转逻辑可用。

本次改动只覆盖 H5 表单的展示、交互和前端必填校验。字段值不写入 `SpeedReport`，不进入本地持久化，也不在后续审核详情中展示。

## 已确认范围

- 所有模板前两行固定为“标题名称”和“内容描述”。
- 首页第一个模板“突发事件速报模板”包含全部新增控件。
- 其余三个模板按业务场景组合部分控件。
- 支持数字、日期、单选框组、多选框组、下拉单选、下拉多选、链接、附件和静态文本提示。
- 新增控件必填校验在提交前执行，校验失败时沿用现有字段错误和 Toast 交互。
- 模板切换时清空该模板的附加字段值，避免不同模板的数据串联。
- 新增控件值只存在于 `ReportView` 当前表单状态中，不改变上报数据结构。

## 字段模型

在 `types.ts` 中新增模板字段配置类型：

```ts
export type TemplateFieldType =
  | 'number'
  | 'date'
  | 'radio'
  | 'checkbox'
  | 'select'
  | 'multi_select'
  | 'link'
  | 'attachment'
  | 'static_text';

export interface TemplateFieldOption {
  label: string;
  value: string;
}

export interface TemplateExtraField {
  id: string;
  label: string;
  type: TemplateFieldType;
  required?: boolean;
  placeholder?: string;
  options?: TemplateFieldOption[];
  content?: string;
  accept?: string;
  multiple?: boolean;
  min?: number;
  max?: number;
  defaultValue?: TemplateFieldValue;
}

export interface ReportTemplate {
  // 现有字段保留
  extraFields: TemplateExtraField[];
}
```

动态值使用以下联合类型保存：

```ts
type TemplateFieldValue = string | string[] | number | null;
```

附件控件仅在当前表单状态中保存文件名数组，不执行真实文件上传。

## 通用渲染器

新增 `TemplateExtraFields.tsx`，职责为：

1. 根据 `extraFields` 渲染对应控件。
2. 接收字段值、错误状态和变更回调。
3. 对链接执行 `http://` 或 `https://` 格式校验。
4. 对附件展示文件名并允许重新选择或清空。
5. 静态文本提示只展示内容，不产生字段值。

渲染器不负责提交、审核人校验和上报数据组装，避免与 `ReportView` 的业务职责耦合。

## 表单状态与校验

`ReportView` 维护：

```ts
const [extraFieldValues, setExtraFieldValues] = useState<
  Record<string, TemplateFieldValue>
>({});
const [extraFieldErrors, setExtraFieldErrors] = useState<
  Record<string, boolean>
>({});
```

- 初次进入模板时，按 `defaultValue` 或空值初始化。
- 切换模板时，重建附加字段状态。
- 提交时先执行原有必填校验，再校验新增必填字段。
- 第一个错误字段滚动到可见区域，并显示“请完善必填项：字段名称”。
- 链接非空但格式错误时显示“请输入正确的网址，需以 http:// 或 https:// 开头”。
- 新增字段校验通过后，继续执行现有审核人缺失校验。
- 审核人阻断逻辑和提示文案保持不变。

## 模板字段组合

### 突发事件速报模板

包含全部控件：

- 数字：现场涉及人数。
- 日期：事件发生日期。
- 单选框组：事件紧急等级。
- 多选框组：信息传播渠道。
- 下拉单选：主要责任部门。
- 下拉多选：需要联动处置的单位。
- 链接：权威信息或现场来源链接。
- 附件：现场照片、视频或处置材料。
- 静态文本提示：提示上报人确保时间、地点和事实要素准确。

### 民生诉求核查模板

- 日期：诉求发生日期。
- 单选框组：诉求紧急程度。
- 多选框组：群众反映渠道。
- 下拉单选：牵头办理部门。
- 附件：诉求截图或现场材料。
- 静态文本提示：提醒区分个人诉求与共性民生问题。

### 网络谣言线索模板

- 日期：线索发现日期。
- 多选框组：传播平台。
- 下拉多选：证据材料类型。
- 链接：谣言原文或传播页面。
- 附件：截图、录屏或核实材料。
- 静态文本提示：提示保留原始链接和传播证据。

### 专项风险线索模板

- 数字：涉及对象或场所数量。
- 日期：风险发现日期。
- 单选框组：风险等级。
- 下拉单选：风险类别。
- 链接：风险来源或佐证链接。
- 附件：联合核查材料。
- 静态文本提示：提示风险事项需同步组织节点审核和终审。

## 页面顺序

1. 标题名称。
2. 内容描述。
3. 现有上报基础字段：发生地址、事件来源、涉及区域、信息类型、核心诉求、处置建议、匹配网络链接。
4. 当前模板附加字段。
5. 提交按钮。

这样既满足固定前两行，又保留现有必填字段、智能比对和上报数据组装能力。

## 边界与异常

- 动态值不进入 `onSaveReport`，因此刷新、切换页面或重新登录后不会恢复。
- 附件只记录文件名，不读取文件内容，不做上传。
- 静态文本提示没有输入控件，不参与必填校验。
- 同一模板重复进入时，动态字段从空状态开始。
- 若模板没有附加字段，仅展示固定字段和现有基础字段。
- 现有审核人阻断必须先于成功提交执行。

## 验证标准

- 四个首页模板均可打开对应表单。
- `突发事件速报模板` 显示全部九类附加控件。
- 其余三个模板显示各自配置的控件，不要求全部出现。
- 必填动态字段为空时阻断提交并聚焦首个错误。
- 链接格式错误时阻断提交。
- 附件选择和清空在当前表单内可交互。
- 切换模板后，上一模板的附加字段值不会残留。
- 提交成功后，原有审核人阻断和上报流程不回归。
- H5 生产构建通过，并且本次修改不新增 TypeScript 错误。
